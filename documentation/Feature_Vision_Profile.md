# Feature Vision — Профиль

## 1. Назначение фичи

Раздел **«Профиль»** объединяет персональный прогресс пользователя по всему Crypto Education и показывает результаты его взаимодействия с обучением, тестами, безопасностью и симулятором.

Фича должна мотивировать пользователя продолжать обучение и давать понятную картину уже пройденного материала.

---

## 2. Пользовательская ценность

Пользователь может:

- видеть общий прогресс;
- понимать, какие темы уже изучены;
- видеть результаты мини-тестов;
- отслеживать активность в симуляторе;
- видеть количество пройденных кейсов по безопасности;
- получать достижения за ключевые действия;
- быстро возвращаться к незавершённому обучению.

Ключевой принцип:

> **Профиль показывает не просто статистику, а путь пользователя внутри образовательного продукта.**

---

## 3. Основные модули

### 3.1. Общая информация

В профиле отображаются:

- nickname или имя пользователя;
- визуальный уровень/статус;
- крипто-робот;
- общий процент прогресса.

### 3.2. Прогресс обучения

Показывается:

- количество пройденных уроков;
- общее количество уроков;
- прогресс по каждому направлению;
- результаты мини-тестов;
- последний открытый урок.

### 3.3. Безопасность

Показывается:

- количество изученных кейсов;
- прогресс по базе угроз;
- связанные достижения.

### 3.4. Симулятор

Показывается краткая статистика:

- количество виртуальных операций;
- активность пользователя;
- при необходимости текущая стоимость виртуального портфеля.

Профиль не должен превращаться в полноценный торговый кабинет.

### 3.5. Достижения

Примеры достижений:

- **Первый урок**;
- **Тест-мастер**;
- **Безопасный пользователь**;
- **Первые инвестиции**;
- **5 уроков завершено**;
- **Изучил основы Blockchain**.

---

## 4. Основной пользовательский сценарий

1. Пользователь открывает **«Профиль»**.
2. Видит общий прогресс.
3. Смотрит прогресс по образовательным направлениям.
4. Видит результаты и статистику.
5. Просматривает достижения.
6. При необходимости нажимает на незавершённую тему и возвращается к обучению.

---

## 5. Система прогресса

Для MVP прогресс должен быть максимально прозрачным.

Возможная формула:

**Прогресс направления = завершённые уроки / общее количество уроков × 100%.**

Общий образовательный прогресс может рассчитываться по всем урокам.

Необходимо отдельно показывать:

- обучение;
- тесты;
- безопасность;
- симулятор.

---

## 6. Достижения

Достижения используются как лёгкая геймификация.

Каждое достижение имеет:

- название;
- иконку;
- описание;
- условие получения;
- состояние: получено / не получено.

Достижения не должны быть критичны для доступа к функциям.

---

## 7. Бизнес-правила

- Прогресс обновляется после завершения соответствующего действия.
- Удаление или сброс прогресса в MVP не требуется.
- Достижение выдаётся автоматически после выполнения условия.
- Одно достижение выдаётся один раз.
- Заблокированные достижения можно показывать пользователю заранее.
- Профиль не должен отображать чувствительные финансовые данные.
- Крипто-робот может использоваться как визуальный элемент профиля и показывать короткие мотивирующие сообщения.

---

## 8. Основные состояния

### Профиль

- новый пользователь;
- пользователь с частичным прогрессом;
- пользователь с завершёнными направлениями.

### Достижение

- заблокировано;
- получено.

---

## 9. Что не входит в MVP

- социальный профиль;
- друзья;
- рейтинги пользователей;
- лидерборды;
- публичная статистика;
- персональные финансовые рекомендации;
- сложная система уровней;
- платные достижения;
- NFT-награды;
- редактирование расширенных персональных данных.

---

## 10. Критерий готовности фичи

Фича готова к MVP, если пользователь может:

> открыть профиль → увидеть общий прогресс → увидеть прогресс по темам → посмотреть результаты активности → увидеть полученные и будущие достижения → вернуться к незавершённому обучению.
